# AGENTS

- Run `src/setup.ts` to (re)create command wrappers for scripts. Add new scripts to `src/scriptCommands.ts`
- New scripts should have Bun shebangs and be executable.
- Use `createScript(scriptName)` from `src/utils/createScript.ts` for every CLI, importing it before modules with startup side effects (including `env`). Do not instantiate yargs directly. The shared factory provides deferred asynchronous startup, centralized parser/handler error reporting with exit status 1, local defaults, `.help()`, `.strict()`, full help on failure, no `--version`, and terminal-width wrapping. Use reasonable argument types and descriptions where not obvious.
- `defaults.ts` at the repo root is gitignored and copied from `defaults.example.ts` on first startup, including when invoked through a wrapper from another directory. It default-exports a partial `ScriptDefaults` map; scalar/array entries are option defaults and nested objects scope defaults to subcommands, e.g. `{ '222': { invites: { format: 'rich' } } }`. Precedence: explicit flags > deepest command defaults > parent/script defaults > built-in defaults. Use canonical command names and option names; registered script aliases share defaults, with the canonical script name taking precedence. Keep the example free of personal values and secrets.
- Startup warns about unknown script names in `defaults.ts`. Before parsing, `createScript` checks all configured commands/options for that script, including inactive nested commands, and warns with the full path while ignoring unknown entries. Command builders must only declare CLI structure; put work with side effects in handlers, since validation also runs builders.
- Register commands through the shared parser's `.command()` and finish with `.parseAsync()` (or `.parseSync()`/`.parse()`) so defaults apply after option declarations. Prefer `.parseAsync()` for entry points; it defers handlers until module initialization finishes and reports failures centrally. Use `.exitProcess(false)` when embedding/testing to receive thrown errors. Do not wrap the parser in another `createScript` callback or a catch that only logs and exits. The Git commit wrapper uses this same parser for its own `--who` option and forwards Git arguments unchanged.
- if interactivity is desired see how other scripts in this repo do it and use the same libs
- read project environment variables directly from `src/env.ts` (default `env` object) only; do not add other env parsing/loading utilities. keep system vars (like `HOME`/`SHELL`) on `process.env`. when env keys change, run `env-manager ts` to regenerate `src/env.ts`
